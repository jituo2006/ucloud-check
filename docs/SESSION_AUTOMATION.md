## 需要填写

在被 Git 忽略且权限为 600 的 `cloudflare/.dev.vars` 中填写：

```dotenv
UCLOUD_TOKEN="登录后 Cookie 的 token"
UCLOUD_REFRESH_TOKEN="同次登录 Cookie 的 refresh_token"
```

已生成 `SESSION_SECRET`，保留即可。不要将实际值发送到聊天、提交 Git，或覆盖已有服务密钥。两个 Cookie 应来自同一个账号的同次登录。

获取位置：Chrome 打开已登录的云邮网页 → 开发者工具 → Application（应用）→ Storage → Cookies → 云邮域名。复制 `token` 和 `refresh_token` 的 Value 到对应本地配置。Cookie 名中有下划线；配置变量使用上面的大写名称。

课前检测还需要准确的课表日期、周次和课程起止时间。现阶段支持 `CLASS_WINDOWS` 中的日期窗口，格式参考 `cloudflare/classes.example.json`；该文件只是格式示例，没有作为真实课表启用。没有课表时，只能在低频检查发现进行中课堂后切换高频，无法保证课前唤醒。

## 登录如何维持

公开前端使用 `/ykt-basics/oauth/token`，表单 `grant_type=refresh_token`。服务在只读请求收到 HTTP 401 时刷新并重发一次只读请求；取得 `expires_in` 后，在令牌接近过期时提前刷新。新 access/refresh token 使用 AES-GCM 加密后存入 D1，加密密钥保存在 Worker Secret。新令牌优先于初始环境变量使用，Worker 重启后仍可读取。

刷新通过 D1 锁串行执行。刷新前持久化处理中标记；平台拒绝或响应丢失时停止自动刷新，避免反复使用可能已轮换的旧刷新令牌。重新登录并填写新的两个 Cookie 会替换旧会话。若学校撤销会话、刷新令牌过期或要求重新认证，仍需本人登录，不能承诺永久在线。

真实签到写请求不会因为收到 401 而自动重复提交；未知结果需要查询云邮记录。
