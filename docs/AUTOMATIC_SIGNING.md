# 自动签到试运行

2026-11-13，用户明确要求“正常开启……检测开启，试一试能不能自动签到”，该指令取代此前仅提醒或手机确认的运行选择。

```toml
ENABLED = "true"
ENABLE_ATTENDANCE_MONITOR = "true"
ENABLE_SIGNING = "true"
AUTO_SIGN = "true"
SIGNING_PROTOCOL = "plugin"
ENABLE_ATTENDANCE_PROBE = "false"
```

## 实际流程

课表窗口内每分钟检测 → 发现本人当前课堂 → 调用原插件的基础签到接口 → 正数活动 ID → D1 去重 → 自动领取 → 重查本人、课堂和活动 → 读取 clock → 提交一次 → 尝试查询本人记录核对 → Bark 发送结果。

`plugin-signing.mjs` 沿用原插件 `autoSign()` 的候选标准，不要求原插件未使用的个人状态字段。响应中已有的时间、课程和课次信息仍校验：未来或已过期的活动不处理，课程或课次不匹配不处理。缺少结束时间时，本地处理窗口最长五分钟；这不代表学校一定开放五分钟，最终以学校是否接受为准。

`OPEN_STATUSES`、`UNSIGNED_PATH`、`UNSIGNED_VALUES` 在 `plugin` 模式不作为强制前提；切回严格校准协议时仍需要这些值。

自动模式不等待手机确认；关闭 `AUTO_SIGN` 可恢复确认路径。关闭 `ENABLE_SIGNING` 则不提交，检测开关独立。Bark 故障不阻塞已经授权的自动尝试。

## 去重与结果

事件键包含本人账号、课程、课次和签到 ID；D1 条件更新领取，同一活动不因重复扫描再次提交。写请求超时、网络中断或业务结果未确认时记录未知，不自动重发。

提交前尽可能检查本人记录；使用活动 ID 或完全相同的点名起始时间匹配，出现多条匹配时不当作确定证据。本轮已有正常、迟到、早退或请假等记录时跳过，避免覆盖。

结果含义：

- `verified`：请求被平台接受，且匹配到本轮正常/迟到/早退记录。
- `accepted`：请求被平台接受，独立记录尚未确认。
- `already_signed`：本轮已有到课或请假记录，未重复提交。
- `failed`：提交前校验未通过。
- `unknown`：发出写请求后的结果未确认，不重试。

管理状态接口新增 `recentAttendance` 和候选数量，便于核对实际发生了什么。独立采样关闭后不持续保存响应结构。

## 验证边界

49 项模拟测试通过，覆盖自动模式只提交一次、已有记录跳过、提交关闭、超时不重试、Bark 失败不阻塞、活动边界和记录精确匹配。真实课堂是否已经提交或成功，需要根据实际监测及记录判断。
