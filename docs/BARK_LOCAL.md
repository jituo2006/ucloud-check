# Bark 通知与本人确认：本地版本

本版本为待联调的本地实现，默认关闭后台监测。没有服务器时，先使用离线演示；部署公网 HTTPS 和配置 Bark 另行完成。云邮实际签到状态及本人未签到字段尚待正常课堂抓包校准，未校准前不会创建签到确认或自动提交。

## 本地演示

构建插件需要 Node.js 20.19+ 或 22.12+ 及 pnpm；运行当前完整模拟测试集需要 Node.js 22.12+（本轮使用 22.22）。

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm lint:monitor
pnpm build
pnpm relay:demo
```

浏览器打开 `http://127.0.0.1:8787/demo`，可看到模拟课程的手机确认页。`--demo` 不会访问 Bark 或云邮，点击按钮只把模拟活动改为已确认，没有真实插件接收命令，不会签到。重新打开 `/demo` 可以生成新的模拟活动。结束服务按 Ctrl+C。

`dist/` 是构建后的扩展目录。安装、刷新扩展及授予新增权限需要用户在 Chrome 中操作，本轮没有安装或启用。

## 实际运行时的配置

先在 iPhone 安装 Bark，并验证 App 自带测试能正常送达。然后：

```bash
pnpm relay:init
# 在本地编辑 relay/.env，填写 BARK_DEVICE_KEY
pnpm relay
```

初始化脚本生成独立随机的 `RELAY_KEY` 与 `CONFIRM_SECRET`，以仅本人可读写的文件保存；不输出密钥、不覆盖已有 `.env`。`.env` 和中转状态目录均被 Git 忽略。不要将设备密钥、云邮令牌或配置文件提交到仓库。

配置字段：

| 字段 | 用途 |
| --- | --- |
| `BARK_DEVICE_KEY` | Bark App 提供的设备 key，仅填 key，不是完整推送 URL |
| `RELAY_KEY` | 扩展连接中转服务的凭证，复制到扩展监测设置 |
| `CONFIRM_SECRET` | 为每轮手机确认链接签名，与连接凭证分开 |
| `PUBLIC_BASE_URL` | 手机能访问的中转根地址；正式使用需 HTTPS |
| `HOST` / `PORT` | 默认只监听 `127.0.0.1:8787`，供本地或同机反向代理访问 |
| `STATE_FILE` | 待确认事项与处理状态；生产运行应持久化该目录 |

`127.0.0.1` 指设备自身，iPhone 无法通过这里的电脑回环地址访问服务。因此本地版可演示页面和运行模拟测试，手机真实确认需要后续部署 HTTPS 中转或明确配置可达的私有连接。此版本没有自动开隧道或暴露电脑端口。

## 扩展设置

构建并由用户加载扩展后，在设置页“手机提醒与确认签到”中填写中转地址和 `RELAY_KEY`。点击保存时，Chrome 只请求该中转来源的可选访问权限。新增必需权限是 `alarms` 和业务 API 域名；中转域名通过可选权限单独申请。

首次接入需根据本人正常课堂响应校准，不能使用测试中的示例值：

- `attendanceBasicInfo.attendanceBasicStatus` 的真实开放值。
- `attendanceStartTime`、`attendanceEndTime` 的格式和时区；当前适配器将无时区的年月日时分秒按北京时间解析。若后端返回其他格式，须调整适配器后再启用。
- 同一响应中本人未签到状态的字段路径与值；路径相对于接口的 `data` 对象。例如测试中的 `person.signed` 仅为模拟字段，**不是已确认的真实平台字段**。字段不存在、值未知或已完成时，不发送确认、不提交。

后台每分钟观察课堂；每 30 秒尝试领取已确认事项。Chrome 调度可能延迟，不是实时保证；电脑休眠、Chrome 关闭、会话过期或中转离线时无法保证送达和执行。首次监测把已有课堂建立为基线，后续新课堂才发送开课通知；已核实且尚未完成的有效签到可在首次监测发送提醒。

## 确认与结果

1. 插件发现一轮有效、本人尚未完成的签到，将最小课程摘要发送给中转。
2. 中转用 Bark 推送通知；通知链接打开手机确认页。
3. 打开链接、预览链接和读取状态都不会签到；只有点击“确认签到”才会产生确认命令。
4. 电脑领取命令后重查账号、课堂、活动 ID、本人状态与有效期，再提交一次。
5. 业务响应 `code === 200` 时显示“平台已接受请求”。这是业务接受，不是独立查询记录后的“已确认到课”；后者仍需核对真实记录接口。

确认有效期取活动剩余时间与 5 分钟中较短者。同一活动去重，确认命令只领取一次，执行前持久化提交标记。提交超时或 worker 中断时结果为未知，不盲目重试；请查看云邮记录。电脑未领取时过期的命令不会执行。停止监测后不再领取新命令；在途提交若已发出，则以实际平台结果为准。

只有中转活动摘要、确认能力链接与处理状态发送至手机链路，云邮 token 留在电脑端。手机页面没有任意脚本或 shell 命令入口。

## 验证范围

- 离线测试使用模拟平台、模拟 Bark 和临时本地 HTTP 端口。
- 覆盖未经确认、活动过期、活动变化、本人已完成/状态未知、账号变化、业务拒绝、超时、重启恢复和推送失败等场景。
- 真实 Bark 推送、真实课堂字段校准和手机到公网中转的通信未实测。
- 原仓库的全量 ESLint 存在历史错误；新增文件单独检查，TypeScript/Vite 构建与测试另行验证。

本轮验证结果：14 项模拟测试通过；`pnpm lint:monitor` 和生产构建通过；以 390px 手机宽度检查确认页面，无横向溢出、确认按钮高度 52px。全量 `pnpm lint` 的 10 个错误和 5 个警告已与原始提交逐文件对照，均为原仓库历史问题。
